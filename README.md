# farm-robot

Бот для рыбалки в World of Warcraft. Поплавок ищет сопоставлением с эталонами
прямо в процессе, поклёвку определяет по звуку всплеска. Жмёт и двигает мышь
через Arduino Pro Micro — для игры это настоящие USB-клавиатура и мышь.

## Цикл

1. Пауза `human.beforeCast`, заброс (`keys.cast`).
2. Ожидание поплавка: область `search.width×height` вокруг того места, где его
   показали, сопоставляется со всеми эталонами каждые 300 мс до
   `timing.castTimeout`. В лог — счёт каждого эталона в процентах.
3. Мышь встаёт на поплавок (в случайную точку ±`human.aimJitter`), под
   курсором проверяется, что это он.
4. Ожидание всплеска — громкость в `splash.threshold` раз выше фона. Пока ждём,
   мышь шевелится (`human.idleEvery`, `human.idleSize`).
5. По всплеску — пауза реакции `human.reaction`, мышь обратно на поплавок,
   `Shift+ПКМ`. В лог — на каком уровне сработало.
6. Иногда мышь отводится в сторону (`human.wander`); раз в `human.breakEvery`
   забросов — перерыв `human.breakFor`.

Раз в `timing.baitInterval` — наживка (`keys.bait`).

## Запуск

```
go build -o youtube.exe .
```

и запуск `youtube.exe` **из папки проекта** (или ярлыком с этой рабочей
папкой): `props.yaml`, `templates/`, `mouse.json` ищутся относительно неё. Для
разработки — `go run .`.

Нужен Go 1.25+ и cgo (на Windows — gcc). На Linux — сессия X11 и
monitor-источник PulseAudio/PipeWire.

При первом запуске эталонов нет: заброси удочку руками, наведи мышь на поплавок
и нажми **F6**. Снимок 41×41 ляжет в `templates/bobber/`, а область поиска
встанет вокруг этой точки — она сохраняется в `templates/bobber/anchor.json`,
так что после перезапуска F6 не нужен. Дальше бот поедет сам. F6 работает и во
время рыбалки: на новом водоёме или после сдвига камеры просто нажми ещё раз —
снимется эталон и переедет область.

Клавиши: `F2` пауза, `F3` продолжить, `F4` выход, `F6` снять эталон. На
Windows они опрашиваются, а не ловятся системным хуком: подвисший бот не
тормозит компьютер.

В игре: оконный режим, музыку и ambience выключить, Sound Effects оставить.

## Настройка

Всё в [props.yaml](props.yaml). Подобрать надо два места.

**Бинды** `keys.cast` / `keys.bait` — должны совпадать с игрой. На чистой
установке ничего не забиндено.

**Пороги звука** — через

```
go run . -tune-audio
```

Забрось, дождись поклёвки, посмотри на строку; `<<` означает, что при текущих
порогах сработало бы. По Ctrl+C предложит значения.

`loot.shift`: Shift в WoW инвертирует автолут. Если в игре он включён — `false`,
иначе Shift его выключит и рыба останется в открытом окне.

## Когда что-то не так

```
go run . -trace
```

Каждый цикл по шагам, с временем:

```
---------- цикл 3 ----------
  [    0s /     0s] область 320x220 в (510,270), эталонов 4
  [  152ms /  154ms] заброс ctrl+k
  [  1.52s /  1.67s] после заброса: звук x4.2 к фону, вода изменилась на 3.8%
  [   19ms /  1.69s] сопоставление: 0.812 (bobber-001.png), порог 0.60
  [    1ms /  1.69s] поплавок в (612,340) с 1-й проверки
  [  204ms /  1.90s] под курсором поплавок, счёт 0.84, доводка (+3,-1)
  [   1.5s /  3.40s] жду всплеск, до 22s
  [  6.50s /  9.90s] всплеск
  [   12ms /  9.91s] снимок клика: trace/bite-003.png
  итог: добыча забрана, цикл занял 11.7s
```

Строка «после заброса» отличает две поломки, которые иначе выглядят одинаково:
**звука нет и вода не изменилась** — клавиша до игры не дошла, дело в фокусе или
бинде; **звук был и вода изменилась** — заброс есть, поплавок не распознан,
нужен эталон. При каждой поклёвке сохраняется `trace/bite-NNN.png` с красным
крестом в точке клика.

Эталон ровной воды без поплавка (снятый мимо) не загружается и не снимается:
корреляция с ним «находит» поплавок где угодно. Совпадение, которое стояло на
том же месте до заброса, тоже не считается поплавком — это интерфейс или камень.


Без `-trace` бот тоже объясняет промахи: почему не услышал поклёвку, что было
под курсором, сдвинулась ли область поиска.

## Плата

Весь ввод — клавиши, кнопки и движение мыши — идёт через Pro Micro со скетчем
[arduino/hid_emulator](arduino/hid_emulator/hid_emulator.ino): это
[hid_emulator](https://github.com/mvandrew/arduino-hid-emulator) с исправленным
`mouse_move` (оригинал терял сдвиг по оси, когда кривая выгибалась за цель, и
вёл S-образной кривой с постоянной скоростью). Порт — `input.arduino` в
`props.yaml` (`auto` или `COM4`). Прошивать как Arduino Leonardo или SparkFun
Pro Micro **5V/16MHz**: с 8MHz плата пропадает с USB. Пока бот запущен, порт
занят — Arduino IDE в неё не зальёт. USB-мышь двигается только относительно,
поэтому курсор доводится до точки по обратной связи.

## Движения мыши

Лучше всего — ваши собственные. Запишите несколько минут обычных движений
(переходы разной длины во все стороны, покачивания, с паузами между ними):

```
go run ./cmd/mouserec -d 3m -still 150ms
```

Запись дописывается в `mouse.json` (`human.recording`). Переходы бот берёт из
неё, подгоняя движение похожей длины под цель; шевеления при ожидании поклёвки
проигрывает как есть. Без записи — синтетика: дуга Безье скетча и фигуры
(восьмёрка, круг, влево-вправо). Посмотреть:

```
go run ./cmd/mousedemo -n 10
go run ./cmd/mousedemo -idle 8 -size 60
```

## Метрики

`http://localhost:9100/metrics` — забросы, поклёвки, добыча, промахи по причинам,
уровни звука, счёт сопоставления, доводка мыши перед кликом. Мониторинг:

```
docker run -p 9090:9090 -v ./prometheus:/etc/prometheus/ prom/prometheus
```
